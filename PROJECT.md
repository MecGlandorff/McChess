# McChess

## One-Line Description

McChess is a compact neural chess research system trained without Stockfish, Syzygy, or external engine labels.

## Research Goal

Study how board representation, temporal context, attention, policy/value learning, MCTS, and search distillation interact in a low-compute chess agent trained from human games and optional self-play.

## Central Research Question

How far can a compact neural chess engine go using only human games, architectural inductive biases, search, and self-play without engine supervision?

## Non-Goals

This project is not trying to:

- beat Stockfish
- maximize Lichess Elo at all costs
- use engine evaluations as labels
- use tablebases
- hide weak results
- build a giant model requiring large-scale compute

## Core Claims To Test

1. A policy/value network trained on human games can beat simple handcrafted baselines.
2. Legal move masking is essential for reliable play.
3. MCTS improves move selection over policy-only inference.
4. Temporal context may improve policy prediction and value calibration.
5. Attention may improve global board reasoning or temporal recall.
6. Search distillation may improve the policy without engine labels.
7. A compact NNUE-style sparse accumulator may offer a useful speed/quality
   tradeoff if trained only from allowed McChess targets.

## Allowed Supervision

Allowed:

- human PGN games
- final game result
- self-play results
- MCTS visit counts generated by this project's own model

Not allowed:

- Stockfish evaluations
- Leela evaluations
- tablebase labels
- external engine move recommendations
- pretrained chess-engine policy/value targets

## Main System Components

- PGN parser
- board tensor encoder
- move-indexing layer
- legal policy mask
- policy/value neural networks
- handmade baseline bots
- MCTS
- arena evaluation
- optional temporal models
- optional NNUE-style sparse accumulator models
- optional search distillation
- optional self-play

- reproducible evaluation
- clean engineering under constraints

## Success Standard

McChess is successful if it becomes a compact, reproducible neural-chess research platform with honest measurements.

The project should be judged by:

- correctness of chess rules and tensor contracts
- clarity of implementation boundaries
- reproducibility of datasets, training runs, and evaluations
- quality of baselines and ablations
- honesty of reported strengths and failures

It should not be judged by unsupported Elo claims or by whether it competes with modern engines.

## Evidence Ladder

Claims should follow this progression:

1. import and unit tests pass
2. chess-rule edge cases are tested
3. tiny data pipeline works from PGN to supervised samples
4. model overfits a tiny dataset
5. policy/value training produces saved metrics and checkpoints
6. arena evaluation runs reproducibly against simple baselines
7. MCTS improves or fails to improve the same checkpoint under a fixed protocol
8. architecture or representation ablations are compared under matched configs
9. search distillation or self-play is evaluated with before/after results

Do not skip directly from implementation to strength claims.

## Reportable Output

Reportable experiments must be backed by:

- dataset manifest
- model and training configs
- evaluation config
- random seed
- checkpoint identifier
- metrics file
- results file
- git commit if available
- hardware/runtime notes where available

Negative and inconclusive results should be recorded when they answer a research question.
