# PR review notes - 17-6-2026

These are review comments for the MCTS PUCT PR.

## 1. Notebook MCTS draw/repetition history

File: `src/mcchess/bots/notebook.py`

Status: resolved in the current working tree.

`_bot_move()` now passes `board.copy(stack=True)` into the bot, so MCTS-backed
notebook play preserves the move stack needed by
`board.outcome(claim_draw=True)` for repetition and claimable draw handling.
The original concern was valid when the notebook passed `stack=False`.

Suggested PR comment:

```text
Resolved: MCTS-backed notebook play now passes board.copy(stack=True), matching
the arena path's preservation of repetition and claimable draw history.
```

## 2. Report wording says model calls, but the budget is simulations

File: `reports/2026-06-17-mcts-puct-explainer.md`

The implementation fixes the number of MCTS simulations, not exactly the number
of model calls. The root is evaluated before the simulation loop, and terminal
leaves do not need a model call.

Suggested PR comment:

```text
This should say fixed number of simulations rather than fixed number of model
calls. In the implementation, the root is evaluated before simulations, and
terminal leaves can avoid model evaluation.
```

## 3. `MCTSSearch` assumes eval-mode model

File: `src/mcchess/search/mcts.py`

`load_policy_value_checkpoint()` returns an eval-mode model, so current CLI and
arena usage are okay. But `MCTSSearch` accepts any `PolicyValueModel` and does
not enforce or document eval mode. If future models add dropout or batch norm,
direct callers could get nondeterministic search.

Suggested PR comment:

```text
Should MCTSSearch either call eval() when the passed model is a torch.nn.Module,
or explicitly document that callers must pass an eval-mode model? Current
checkpoint loading does this, but the search API itself does not enforce it.
```
