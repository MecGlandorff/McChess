# Model Card

## Model Name

McChess

## Model Type

Compact neural chess policy/value model.

Potential architectures:

- ResNet
- NNUE-style sparse accumulator, if implemented
- History ResNet
- ResNet + square attention
- LSTM history
- LSTM + temporal attention
- Temporal Transformer

## Intended Use

This model is intended for research.

It is designed to study:

- board representation
- supervised chess policy learning
- value prediction
- legal move masking
- neural search
- MCTS
- temporal modeling
- search distillation
- optional self-play
- optional NNUE-style sparse architecture exploration

## Not Intended For

- competing with modern chess engines
- providing authoritative chess analysis
- replacing Stockfish, Leela, or tablebase analysis
- making claims of high Elo without careful measurement

## Training Data

Allowed training data:

- human PGN games
- game results
- self-play games generated by this project
- MCTS visit counts generated by this project

Disallowed training data:

- Stockfish labels
- Leela labels
- Syzygy tablebase labels
- external engine evaluations
- external best-move recommendations
- imported Stockfish NNUE weights or pretrained chess-engine networks

## Training Objective

The base supervised objective uses:

- policy loss against the human move
- value loss against final game result from side-to-move perspective

Optional later objectives:

- MCTS visit-count distillation
- self-play policy/value targets
- NNUE-style policy/value architecture trained only from allowed McChess targets

## Inputs

The model receives encoded chess positions.

Depending on architecture, input may be:

```text
[batch, planes, 8, 8]
```

or:

```text
[batch, history_length, planes, 8, 8]
```

## Outputs

The model outputs:

```text
policy_logits: [batch, 4672]
value: [batch]
```

The value is from the side-to-move perspective.

## Legal Move Handling

The model does not decide move legality.

Legal move masks are generated explicitly using python-chess.

Illegal moves must be masked before move selection and MCTS expansion.

## Evaluation

The model should be evaluated against:

- random legal-move bot
- material-count bot
- shallow minimax bot
- policy-only neural bot
- policy/value + MCTS bot

Evaluation should report:

- win/draw/loss
- score percentage
- MCTS budget
- speed
- number of games
- random seed
- evaluation protocol

## Known Limitations

Expected limitations:

- weak tactical depth without MCTS
- limited endgame understanding without tablebases
- possible human-game bias
- value head may be noisy because final result is a weak target
- temporal models may be slower than simpler ResNets
- attention weights are not guaranteed to be faithful explanations

## Ethical And Scientific Notes

The project should not overstate strength.

Prefer precise claims:

```text
In a local arena under protocol X, model A scored Y against baseline B.
```

Avoid unsupported claims:

```text
This model is 2000 Elo.
```

unless directly measured with a credible protocol.
